# The teaching view

Each student's `COMPETENCY.md`, the patrol's decisions, the quick-check results and the voice use were files and database rows nobody read. `portal/web/team.html` shows them to the
teaching team: **read-only, owner role only, nothing a student wrote or said**. Code: `src/portal/team.ts` (the aggregation, with injected providers), `src/portal/team-routes.ts` (the
routes and the one function `start.ts` calls), `src/portal/testing/team-fixture.ts` (a synthetic class as real files), `portal/web/{team.html,team.js,team-data.js,team.css}`.

## Who may open it

The owner (`role: "owner"` in `users.json`; `features.team` in `GET api/me` is true for them and for nobody else). The account menu then has **Teaching view**, which opens `team.html` in the same tab.
The server refuses both calls to anyone else (401 signed out, 403 `not-owner`); a signed-out visitor who opens the page is sent to the main page, any other account reads "This page is for the
teaching team". To give a TA the role: add their address with `bash deploy/cs6650/tai_live.sh users add EMAIL --owner`, or set `"role": "owner"` on their entry (the file is re-read when it changes).
(The role is only a label elsewhere: an owner has no other rights, and the TA's own chat is a student chat. NOT run: the command above.) The owner's own account is a teaching-team account: it is **left
out of the class's numbers** unless the box "Count the teaching team's own accounts too" is ticked (`?staff=1`), so a TA testing the page does not move them.

## The panels

| Panel | Where the numbers come from | Notes |
| --- | --- | --- |
| At a glance | the panels below | six cards |
| Needs attention | the patrol gate's own signals (`src/patrol-gate.ts` `gatherFacts` + `evaluateGate`, forced `on`: with `TAI_PATROL_GATE=off` the gate reports none) and the days since the student last wrote | **quiet** for `TAI_PATROL_INACTIVE_DAYS` (5) days or more, or never (not counted for a chat registered inside that time); **deadline** (Canvas, not turned in, due before the next patrol: the gate's `due-last`; with no patrol cron known, within 48 h); **overdue** (the gate's `due-late`, 12 to 72 h); **confirmed misconception, open**. The gate stops calling a student quiet after 21 days (it stops nudging them); the page does not |
| Competency heat map | `groups/<folder>/COMPETENCY.md` of every student on the allowlist, read by `src/voice/competency.ts` (all three spellings of a mastery line) | a row for each concept, a column for each student; weakest first = lowest mean confidence among the students with evidence, concepts nobody has touched last; `Assessed`, `Mean`, `Not said aloud` (students who know it, confidence 0.3 or more, and have no `verbal` scope: the voice side's definition of a verbal gap, `interviewProfile`), `Last evidence`. Cells carry a glyph (solid, getting there, just started) and a mark for the verbal gap besides colour; the bands are the student page's (0.7, 0.4). Concepts the host writes under `### Chat sessions` are rows like any other, with that heading as their group. **Download CSV**: one row per student and concept with evidence (what the filter leaves), a quote mark in front of any text that starts `=`, `+`, `-`, `@`, a tab or a carriage return |
| Misconceptions | the Active Misconceptions lines, by the concept they contradict (`findConcept` against the student's own lines) | how many students, and in which state by the patrol's own rules (`CLOSED`, `IDENTIFYING`, `isOpenAndConfirmed`, exported from `patrol-gate.ts` for this): confirmed, candidate, remediated; a line that is `identifying` is not counted. **The belief is never shown**, only the concept; names only in the opened row. "Remediated" is a floor: the protocol moves a resolved line out of the file |
| The teaching patrol | `task_run_logs` joined to `scheduled_tasks` (the prompt carries `[TEACHING_PATROL]`; what `tai_live.sh patrol` reads), last 7 days in the orchestrator's zone; each student's `competency/intervention-log.md` | runs by day, why the gate skipped (its own words, dates and ids taken out so the same reason counts together), recent runs. A **model run shows only that it ran or failed**: its `result` and the `error` column are never read out; a shadow-mode run shows the gate's bracketed reason. The intervention logs are read as the scheduler writes them (`src/intervention-log.ts`: `no-action`, `intervene`, `failed`) and as the model does (the protocol's examples); absent or empty everywhere: that sub-panel is not drawn |
| Quick checks | the history lines `quiz: true` (TAi's question) and the student's tap on them (`choice: {to, index, correct?}`, `correct` set by the server when TAi had marked an answer) | per question as TAi worded it (same words, case and closing mark ignored): answers, graded, % right. A tap on a quick check whose key was dropped is an answer that is not graded; quick replies are not quick checks. **No student is attached to an answer** (the `secret` of a line is never read). Reads the last 4 MB of each history |
| Voice | `store/voice-usage.json` (seconds per student per day, two weeks) and the **headings** of `competency/voice-sessions.md` (calls on file: its newest thirty) | minutes per day, calls, last call, the daily cap (`TAI_VOICE_DAILY_MIN`, 45) |
| Students | the same files | name, record state (has one / none yet / could not be read), concepts met, mean, not said aloud, last evidence, last wrote or called. A name opens the detail: `GET api/team/student?folder=` |

The filter box narrows every panel by its own words (concept, student name, question). The days are the orchestrator's (`TZ`, Pacific live), and the page says "today" by the server's day (`class.today`), not the browser's.

## The calls

* `GET api/team/overview[?staff=1]`: `{generatedAt, cacheSeconds, bands: {solid, gettingThere}, class: {students, withRecord, noRecord, unreadable, staffHidden, includeStaff, inactiveDays, today, canvas: {state: ok|stale|missing, at}, skipped: {records, histories, voiceUsage}}, students: [{id, name, staff, record, touched, mean, verbalGaps, lastEvidence, quietDays}], concepts: [{name, group, touched, mean, stability, levels, noVerbal, last, cells}], misconceptions: [{concept, students, candidate, confirmed, remediated, who: [{id, name, status}]}], attention: [{id, name, reasons}], patrol, quickChecks, voice}`. `concepts[i].cells[j]` belongs to `students[j]`: `[confidence, stability, scopes, last evidence day or '', verbal gap 0|1]`, or `null` for no evidence. `id` is the student's folder.
* `GET api/team/student?folder=s_...`: one student: concepts (weakest first, with `via`), misconceptions (concept and state), what applies to them, the patrol's counts and the decisions of the last 7 days (**with the reason the log gives, clipped to 200 characters**: it is TAi's, never the student's), voice. 400 for a folder that is not one, 404 for one not on the allowlist.
* Both: owner only, `Cache-Control: no-store`, the aggregate cached 60 s in the process (one computation for callers that come together; a failure is not kept). `team.html` and every other `.html` the server serves carry the content policy (`serveStatic`).

## What never leaves the server

A message a student wrote or said, a call's transcript or summary, a file they attached, the text of a note TAi kept (the `memories` table is not touched), a misconception's belief, the learning-style line, the interaction summary, the model's answer in a patrol run, the `error` column, the `secret` of a quick check. `src/portal/team.test.ts` writes a canary into every one of those places (the fixture) and asserts that none is in the overview, in the student calls, or in any of the 13 accounts' details; that the only files the asynchronous reader opens are `intervention-log.md` and `voice-sessions.md` (its headings only: the history is read by file handle, `COMPETENCY.md` by the gate's own reader); and that the history is parsed only on the lines that can be a quick check or a tap.

## Looking at it

`node portal/qa/dev_server.mjs --port=8850 --out=<dir>`, sign in as `dev:ada@example.com` (the owner), account menu, Teaching view (or `/team.html`): twelve synthetic students as real files (Bob strong, Carol a verbal gap, Erin quiet with an open misconception, Ivan who never opened the page, Lena with a file nobody can read, ...). `POST <control port>/team/class?mode=empty` shows an empty class, `mode=full` the class again. The dev build stubs `cron-parser` (which `patrol-gate.ts` imports and a build directory outside the repository cannot find) with one that throws, so there the gate's "next patrol" is unknown and its 48-hour rule applies.

## Verified, and not

Verified by running: `src/portal/team.test.ts` (29), `team-routes.test.ts` (8), `portal/web/team.test.js` (19) on this PC; `team-db.test.ts` (2) on the host (`host_vitest.sh`: the SQL against a real in-memory better-sqlite3, including that the last-message map equals `getLastUserMessageTime` for every chat); the dev server in the in-app browser (Chromium: dark desktop and light tablet width, the filter, the detail, the heat map). On this PC, 107 synthetic students (82 concepts, 42 MB of files) take 0.6 s to aggregate cold, the answer is 339 KB and the longest stall of the event loop was about 30 ms.

**Not verified**: the real class size and the real files (the live allowlist has only the owner today, so the live page would show an empty class until students are added; the real `COMPETENCY.md` and `intervention-log.md` of a class may hold shapes the fixture does not); a real deploy; the **Download CSV** file in a spreadsheet (the text is tested, the click only in Chromium); a screen reader, Safari and a phone; `portal/qa/portal_e2e.py` (no Playwright here: I changed its account-menu check to count only the items that are drawn, and wrote no flow for this page). **Known limits**: the heat map is a table of about 80 rows and one column per student, scrolled; its cells are not individually focusable (a screen reader reads each cell's words, the point-and-click inspector under it is for the mouse); assignment names are not in the Canvas snapshot, so a deadline says "Canvas assignment <id>"; the chat history is read from the last 4 MB of each file; a student on the allowlist who has opened the page but never written shows as "has not written yet" once their chat is more than 5 days old.
